Deep Dive · tokipe pipeline

เจาะลึกทีละ Layer

แต่ละ stage ใน pipeline ทำอะไร ทำไมต้องมี และทำงานอย่างไร — พร้อมตอบคำถามเรื่อง multi-agent, ข้าม provider และ backend ภายนอก

request→ preprocess→ tool cache→ RAG→ dedupe→ compress→ history budget→ cache align→ routing→ send
Layer 1

Preprocess

What

ชุด Rule ที่ตรวจจับคำถามที่ตอบได้เองก่อนถึงโมเดล เช่น คำสั่งระบบตายตัว หรือ JSON ที่ parse ได้ตรงๆ

Why

เป็น stage เดียวที่ตัด 100% ของ input tokens สำหรับ turn นั้น เพราะไม่เรียกโมเดลเลย ในเบนช์มาร์ก 3/12 turn จบตรงนี้

How

สอง gate: CanHandle (เร็ว, หยาบ, รันทุก request) แล้วค่อย Handle (ช้ากว่า, แม่นกว่า) คืน nil ได้ถ้าจริงๆ ตอบไม่ได้

preprocess.RuleFunc{
    Match: func(r *pipeline.Request) bool { return r.Query == "/help" },
    Fn:    func(r *pipeline.Request) (*pipeline.Response, error) {
        return &pipeline.Response{Content: menu}, nil
    },
}

กฎ: เข้มงวดไว้ก่อน — คืน false เมื่อไม่แน่ใจ เพราะเรียกโมเดล 1 ครั้งถูกกว่าตอบผิด 1 ครั้งเสมอ ไม่มีโมเดลมาช่วยเช็คตรงนี้

Layer 2

Tool Cache

What

Cache ผลลัพธ์การเรียก tool คีย์ด้วย hash ของ (tool name, arguments) ทั้ง in-memory และ Redis-backed (module แยก)

Why

Tool ถูกเรียกซ้ำด้วย argument เดิมบ่อยมากในเอเจนต์ที่คุยยาว — ประหยัดทั้งค่าเรียก tool และ token ของผลลัพธ์ที่ไม่ต้องส่งซ้ำ

How

Get/Set พร้อม TTL ต่อรายการ, ทุก backend เป็น fail-open (error → miss) และมี singleflight กัน stampede เมื่อเรียกซ้อนกันพร้อมกัน

config.WithToolCache(toolcache.NewMemoryCache(), executor, time.Minute)

turn 1 — executor invocations: 1
turn 2 — executor invocations: 1   // argument เดิม, ไม่รันซ้ำ

ทดสอบด้วย 480 concurrent calls ต่อ shared state พร้อม -race: การเรียกซ้ำที่เหมือนกันทุกตัวยุบเหลือ execution เดียว

Layer 3

Retrieval (RAG)

What

Embed คำถาม แล้วดึง top-K chunk ที่เกี่ยวข้องที่สุดจาก stores.VectorStore มาแปะเข้า request แบบ dynamic content

Why

ทางเลือกคือส่งทั้งเอกสาร/ทั้งฐานความรู้ทุกครั้ง — RAG "เพิ่ม" token ต่อ turn แต่ทำให้ไม่ต้องส่งของที่ไม่เกี่ยวข้องเลย

How

Request-level opt-in ผ่าน NeedsRetrieval: true — ไม่บังคับทุก turn ต้อง retrieve, และ store ใช้ได้ทั้ง mock และ pgvector

ข้อควรระวังเชิงสถาปัตยกรรม: RetrievedChunks เป็น "dynamic" เสมอ — ต้องไม่มี cache breakpoint ไปแตะส่วนนี้ ไม่งั้น provider cache จะ miss ทุก turn เพราะเนื้อหาเปลี่ยนตลอด

Layer 4

Chunk Dedupe

What

ตัด chunk ที่ retrieval ดึงมาซ้ำออก — เกิดบ่อยเมื่อเอกสารเดียวกัน ถูก index ไว้ภายใต้ URL หรือ chunk boundary ต่างกัน

Why

สำเนาที่สองไม่ได้ให้ข้อมูลใหม่กับโมเดลเลย แต่ถูกคิดราคาเต็มเหมือน chunk แรกทุกประการ — เป็นต้นทุนที่ไม่มีประโยชน์อะไรตอบแทน

How

ค่าเริ่มต้นคือ exact normalized-word-sequence match (ปลอดภัย 100%) ส่วน near-duplicate threshold ต่ำกว่า 1.0 เป็น opt-in แบบ lossy ชัดเจน

ทำไมไม่ใช้ fuzzy matching เป็นค่าเริ่มต้น: ในเอกสารยาว คำว่า "allow" กับ "deny" อาจต่างกันแค่คำเดียวแต่ความหมายตรงข้ามกันสิ้นเชิง — ความปลอดภัยของข้อมูลสำคัญกว่าการประหยัดเพิ่มอีกไม่กี่เปอร์เซ็นต์

Layer 5

Compression

What

3 compressor ต่อกันเป็น chain: JSON minifier, Go-source (AST-aware), และ prose whitespace normalizer เป็นตัวสุดท้ายเสมอ

Why

JSON ที่ pretty-print มี whitespace ไร้ประโยชน์เต็มไปหมด ส่วนซอร์สโค้ด Go ที่แปะเข้า prompt มักมี comment ที่โมเดลไม่ต้องใช้ตัดสินใจ

How

CanHandle เช็คก่อนว่า parse ได้ไหม, คืนต้นฉบับกลับ ถ้าผลลัพธ์ไม่เล็กลงหรือ parse ไม่ผ่านซ้ำ — ไม่มีทางเสียหายจากการบีบอัด

config.WithCompression(
    compress.NewJSONCompressor(),
    compress.NewCodeCompressor(), // ลบ comment, เก็บ function body ไว้ (ค่าเริ่มต้น)
    compress.NewTextCompressor(), // catch-all ต้องอยู่ท้ายสุดเสมอ
)

CodeCompressor ปฏิเสธไฟล์ที่มี compiler directive หรือ import "C" และ verify ผลลัพธ์ตัวเองด้วยการ parse ซ้ำเทียบจำนวน declaration

Layer 6

History Budget

What

ตัดบทสนทนาให้พอดี token budget ต่อประเภท turn — policy กำหนด 3 ระดับ: routine resume (4k), new question (12k), error recovery (20k)

Why

ต้นทุนหลักของ agent loop ที่ยาวคือ "ประวัติที่โตไม่หยุด" — ในเทสยาว 100 turn ลดจาก 195,691 เหลือ 88,930 billed tokens (54.6%)

How

ตัด "กลาง" ของบทสนทนา ไม่แตะ static prefix และไม่ทิ้งข้อความล่าสุด — ถ้า fit ไม่ได้ตามกฎ retention จะรายงาน history.over_budget แทนที่จะฝืนตัด

config.WithHistoryBudget(budget.DefaultPolicy(), counter)
req.TurnType = budget.Classify(req)

ทำไมตัดกลางไม่ตัดหัว: ตัดหัวจะเปลี่ยน byte แรกของ prompt ทุก turn ทำให้ provider cache แบบ longest-common-prefix ไม่มีวัน hit เลย

Layer 7

Cache Alignment

What

จัดลำดับข้อความให้เนื้อหาคงที่ (system prompt, tool definitions) มาก่อนเสมอ แล้ววาง cache breakpoint หลัง static prefix นั้น

Why

Provider cache แบบ prefix ทำให้ turn ถัดๆ ไปจ่ายถูกลงมาก — แต่จะได้ผลก็ต่อเมื่อ prefix เหมือนเดิมทุกไบต์ทุก turn

How

ต้องเป็น stage สุดท้ายที่แตะเนื้อหา — รันหลัง RAG, compress, lazyload เสมอ ไม่งั้น breakpoint จะไปตกในโซนที่ยังเปลี่ยนได้

Messages: []pipeline.Message{
    {Role: "system", Content: prompt, Static: true},
    ...
}
config.WithCacheAlignment()
// breakpoints placed = 1, after message 0, reason "static_prefix"

เปลี่ยนแม้แต่ 1 ช่องว่างใน system prompt = cache miss ทุก turn ตั้งแต่นั้น — ยืนยันแล้วกับ Anthropic Messages API จริง: turn 1 เขียน cache, turn 2 อ่านสำเร็จ

Layer 8

Routing

What

ให้คะแนนความซับซ้อนของ request แล้วเลือก ModelClient จาก tier ที่กำหนด — คะแนนเกินทุก tier จะตกไปที่ tier สุดท้าย (แพงสุด) เสมอ

Why

Turn ง่ายส่วนใหญ่ไม่จำเป็นต้องใช้โมเดลแรงสุด — ส่งไปโมเดลถูกลด ค่าใช้จ่ายได้จริงโดยไม่ต้องเขียน if-else เลือกโมเดลเองในทุก endpoint

How

รันหลัง context-shaping stage ทั้งหมด (ไม่ใช่ pipeline.Stage) เพราะต้องเห็น prompt ขนาดสุดท้ายจริงๆ ก่อนตัดสินใจ

router.NewHeuristicRouter(
    router.Tier{Client: cheap,  MaxComplexity: 0.35},
    router.Tier{Client: strong, MaxComplexity: 1.0},
)
// weight: length 0.5, code 0.3, retrieved-chunk count 0.2

Tier.Client รับ pipeline.ModelClient ตัวไหนก็ได้ — นี่คือจุดที่ตอบคำถามเรื่อง cross-provider ในสไลด์ถัดไป

Compatibility Q&A

ใช้กับระบบ multi-agent ได้ไหม?

ได้ — แบบ library ไม่ใช่ orchestrator

tokipe ไม่ใช่ agent framework และไม่ตัดสินใจว่าใคร spawn agent ไหน — มันคือ "ชั้นก่อนเรียกโมเดล" ที่แต่ละ agent เรียกใช้ตอน turn ของตัวเองมาถึง ระบบ multi-agent (เช่น orchestrator ที่คุณเขียนเอง หรือ framework อย่าง LangGraph/CrewAI/AutoGen ที่เรียก Go service ของคุณ) วางไว้ "รอบนอก" pipeline นี้ได้ตามปกติ

สิ่งที่แชร์กันได้ข้าม agent

Tool cache (Redis backend), vector store (pgvector), metrics recorder — ให้ทุก agent instance ชี้ไป backend เดียวกัน ก็ได้ hit rate ที่สูงขึ้นข้าม agent

สิ่งที่ต้องแยกต่อ agent

kit แต่ละตัว (หรือ pipeline instance) ควรมี system prompt/static content ของตัวเอง เพราะ cache breakpoint ผูกกับ prefix ที่คงที่ของ agent นั้นๆ

ไม่มี global mutable state เป็นกฎของโปรเจกต์ตั้งแต่ต้น (ดู PLAN.md) — เพราะแบบนี้เอง หลาย agent จึงรันพร้อมกันแบบ concurrent-safe ได้ โดยไม่ต้องกลัวชนกัน ตราบใดที่ backend ที่แชร์กัน (cache/store) เอง thread-safe อยู่แล้ว

Compatibility Q&A

ทำงานข้าม provider ในระบบเดียวได้ไหม?

ได้ — เป็นฟีเจอร์หลัก ไม่ใช่ workaround

router.Tier.Client รับ pipeline.ModelClient ซึ่งเป็น interface แค่ 2 เมธอด — แต่ละ tier จึงเป็น provider คนละเจ้าก็ได้ ไม่จำเป็นต้องเป็นโมเดลจากค่ายเดียวกัน

cheap  := openai.New(openai.Config{BaseURL: "http://localhost:11434/v1"}) // Ollama
strong := anthropic.New(anthropic.Config{Model: anthropic.DefaultModel})   // Anthropic

kit := tokipe.New(strong, config.WithRouter(router.NewHeuristicRouter(
    router.Tier{Client: cheap,  MaxComplexity: 0.35}, // local model รับ turn ง่าย
    router.Tier{Client: strong, MaxComplexity: 1.0},  // cloud model รับ turn ยาก
)))

ข้อจำกัดที่ต้องรู้

Cache breakpoint (cache_control) เป็นของ Anthropic โดยเฉพาะ — ถ้า tier นั้นเป็น OpenAI-compatible/CLI, breakpoint จะถูกละไว้อย่างปลอดภัย (advisory) แต่ stage อื่นทั้งหมดยังทำงานเหมือนเดิม

พิสูจน์แล้วในโค้ด

examples/local-routing รัน local model กับ cloud model คนละตัวจริงในเวิร์กโหลดเดียวกัน โดยไม่มี if-statement เลือก provider ในโค้ดธุรกิจเลยสักบรรทัด

Compatibility Q&A

Hermes, OpenClaw หรือ backend อื่นที่ไม่ได้ตั้งชื่อไว้ล่ะ?

ในโค้ดของ tokipe ไม่มีการอ้างถึง "Hermes" หรือ "OpenClaw" โดยตรง — คำตอบเลยขึ้นกับว่าเครื่องมือนั้น expose ตัวเองแบบไหน ไม่ใช่ชื่อของมัน

ถ้า backend เป็นแบบนี้ใช้ path ไหนตัวอย่าง
OpenAI-compatible HTTP endpointproviders/openai — กำหนด BaseURL เท่านั้นHermes ผ่าน Ollama/vLLM/Together/OpenRouter, LM Studio
CLI ที่ authenticate ผ่าน subscription อยู่แล้วproviders/cli — รัน executable ตรงๆ ไม่ผ่าน shellมี preset ให้แล้วสำหรับ claude/codex/opencode; CLI อื่นเพิ่ม Config เองได้
อะไรก็ได้ที่เหลือ (custom SDK, gRPC, ฯลฯ)implement pipeline.ModelClient เอง2 เมธอด: Send กับ Name
 
type ModelClient interface {
    Send(context.Context, *pipeline.Request) (*pipeline.Response, error)
    Name() string
}

Hermes โดยเฉพาะ: เป็นโมเดล open-weight ที่มักเสิร์ฟผ่าน server แบบ OpenAI-compatible อยู่แล้ว (Ollama/vLLM/OpenRouter) — เข้าทาง providers/openai ได้ทันทีโดยไม่ต้องเขียนโค้ดเพิ่ม

OpenClaw: ไม่ใช่ชื่อที่ปรากฏในโค้ดเบสหรือที่ผู้เขียนยืนยันได้ว่าคืออะไรแน่ — ถ้าหมายถึงเครื่องมือเฉพาะ ช่วยบอกเพิ่มว่ามัน expose แบบ HTTP API หรือ CLI จะระบุ path ที่แม่นยำให้ได้ทันที
