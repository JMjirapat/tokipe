Why · ทำไมถึงต้องมี

ทุก turn ของแชตบอท/เอเจนต์ ส่งบทสนทนาทั้งหมดซ้ำ

ยิ่งบทสนทนายาว ยิ่งแพง: เอเจนต์ที่คุยถึง turn ที่ 40 ต้องจ่ายค่า token ของ turn ที่ 1–39 ซ้ำทุกครั้ง เอกสารที่ดึงมาซ้ำ (RAG) ถูกแปะซ้ำสอง เครื่องมือ (tool) ที่เคยเรียกไปแล้วก็ถูกเรียกซ้ำ และผลลัพธ์ก็ถูกคิดเงินซ้ำอีกรอบ

ปัญหานี้ไม่ใช่ "โมเดลแพง" แต่คือ ไบต์เดิมที่ถูกจ่ายเงินซ้ำแล้วซ้ำอีก ทุกทีมที่รัน LLM ใน production เจอปัญหานี้เหมือนกัน ไม่ว่าจะใช้โมเดลไหน

ต้องการลดบิล API และ latency โดยไม่อยากเขียน caching/routing เอง ตั้งแต่ศูนย์ และไม่อยากผูกติดกับ framework ใหญ่

Primary

บริษัทที่รัน LLM ใน production ต่อเนื่อง

ปริมาณ traffic สูงพอที่ 1% ของ token ที่ประหยัดได้ = เงินจริงต่อเดือน ต้องการความน่าเชื่อถือ ไม่ใช่แค่ demo

Secondary

ทีมที่ใช้ Claude Pro/Max, ChatGPT Plus subscription

ไม่มี API key แต่มี CLI subscription อยู่แล้ว — ยังใช้ pipeline เดียวกันได้ผ่าน CLI provider

Secondary

Platform / infra team

ต้องการ observability ว่า optimization แต่ละจุดทำงานจริงไหม หรือ "เงียบ" ไปเมื่อ dependency ล่ม

What · คืออะไร

ไลบรารี ไม่ใช่บริการ ไม่ใช่ proxy

tokipe คือ pipeline แบบ opt-in ที่รันอยู่ ก่อน การเรียกโมเดลทุกครั้ง ทำหน้าที่ตัดสิ่งที่ไม่จำเป็นออกจาก request โดยที่ แอปของคุณยังคงเรียกใช้งานผ่านฟังก์ชันเดียว

request→ preprocess→ tool cache→ RAG→ dedupe→ compress→ history budget→ cache align→ routing→ send

Core module import แค่ Go standard library ไม่มี dependency แฝง บังคับด้วย CI ทุกครั้งที่ push ไม่ใช่แค่คำสัญญา

Core Value · คุณค่าหลัก

4 สิ่งที่วางใจได้

💰 ประหยัดจริง วัดได้

57.1% ลด billed input tokens ในเบนช์มาร์ก enforced โดย CI ไม่ใช่ตัวเลข marketing

ใช้ได้กับ Anthropic, OpenAI-compatible, CLI subscription หรือ provider ของคุณเอง

optimization พังได้ แต่ turn ต้องไม่พัง — ทดสอบจริงด้วยการพังทุก dependency พร้อมกัน

🧩 เปิดใช้ทีละส่วน

ไม่เปิดอะไรเลย = pass-through เพิ่มทีละ stage แล้ววัดผลของแต่ละอันเอง

คุณค่าที่แท้จริงของ tokipe ไม่ใช่ "ฟีเจอร์เยอะ" แต่คือ เชื่อถือได้พอที่จะเปิดใช้ใน production จริง

How · ทำงานอย่างไร

เรียกใช้ผ่านฟังก์ชันเดียว pipeline จัดการที่เหลือ

kit := tokipe.New(client,
    config.WithPreprocess(rules...),
    config.WithToolCache(cache, exec, ttl),
    config.WithRAG(embedder, store, 5),
    config.WithChunkDedupe(),
    config.WithDefaultCompression(),
    config.WithHistoryBudget(policy, counter),
    config.WithCacheAlignment(),
    config.WithRouter(router),
)

resp, err := kit.Run(ctx, req)

ลำดับของ stage ถูก "ล็อก" ไว้ตามกฎความถูกต้อง: retrieval และ compression ต้องเสร็จก่อน history budget และ cache alignment เสมอ ไม่ว่าคุณจะเปิดกี่ stage ก็ตาม

ไม่มี global state, ไม่มี daemon, ไม่มี proxy คั่นกลาง traffic ของคุณ — เป็นโค้ดที่รันอยู่ใน process เดียวกับแอปคุณเอง

How it does · กลไกที่ทำให้ประหยัดจริง

ประหยัดจากการ "ไม่ส่งของซ้ำ" ไม่ใช่การบีบอัดสุดโต่ง

Short-circuit ก่อนถึงโมเดล

preprocess จับคำถามที่ตอบได้เองไว้ตั้งแต่ต้นทาง — 3 ใน 12 turn ของ เบนช์มาร์กไม่ถึงโมเดลเลย

Cache ที่ provider คิดเงินถูกลง

cache alignment จัดให้ prefix คงที่ ไบต์ต่อไบต์ ให้ provider เจอ cache hit และคิดราคาถูกลงในส่วนนั้น

ตัด "กลาง" ไม่ตัด "หัว-ท้าย"

history budget ตัดข้อความกลางบทสนทนา เพราะการตัดหัวจะทำให้ prefix เปลี่ยนทุก turn และ cache ไม่มีวัน hit

Route ตามความยาก ไม่ใช่ตามค่าเริ่มต้น

heuristic router ให้คะแนนความซับซ้อนแล้วเลือกโมเดลถูกสำหรับ turn ง่าย โดยไม่ต้องเขียน logic เอง

Fail-open คือกฎเหล็ก: cache พังกลายเป็น miss, retrieval พังคือไม่ส่ง chunk, compressor พังคือคืนของเดิม ไม่มี stage ไหน ทำให้ turn ล้มเหลวได้

Market Size · ขนาดตลาด (ประมาณการ)

ตลาดค่าใช้จ่าย LLM API กำลังโตเร็ว และ "ต้นทุน" คือ pain point อันดับต้นๆ

TAM

องค์กรทุกที่ที่เรียก LLM API

ทุกทีมที่ integrate LLM เข้าโปรดักต์ ต้องจ่ายตาม token — ตลาด LLM inference/API spend ทั่วโลกอยู่ในระดับหลักหมื่นล้านดอลลาร์และยังโตต่อเนื่อง

SAM

ทีมที่ใช้ Go หรือสร้าง agent/RAG

กลุ่มที่สร้าง production agent, RAG chatbot, coding assistant ด้วย backend ที่เขียนได้ด้วย Go — กลุ่มที่โตเร็วตามเทรนด์ agentic AI

SOM

ทีม/โปรเจกต์ open-source adopter รุ่นแรก

Go developer ที่กำลังมองหา library ลดต้นทุนแบบ self-hosted ไม่ต้องพึ่ง SaaS gateway ภายนอก

หมายเหตุความซื่อสัตย์: ตัวเลขข้างต้นเป็น กรอบคิดเชิงประมาณการเพื่อวางตำแหน่งโปรเจกต์ ไม่ใช่ผลวิจัยตลาดที่มีแหล่งอ้างอิงตรวจสอบได้ — ก่อนใช้ตัวเลขนี้ในการตัดสินใจธุรกิจจริง ควรหา market research ที่มีแหล่งที่มาอ้างอิงได้ประกอบ

Example · ตัวอย่างใช้งานจริง

สิ่งที่เล็กที่สุดที่ใช้งานได้ ใน 60 วินาที

import (
    "github.com/JMjirapat/tokipe"
    "github.com/JMjirapat/tokipe/pipeline"
    "github.com/JMjirapat/tokipe/providers/mock"
)

kit := tokipe.New(mock.New("demo-model", "42"))

resp, err := kit.Run(ctx, &pipeline.Request{
    Query: "หกคูณเจ็ดเท่ากับเท่าไร?",
})
content        = "42"
model          = demo-model
shortCircuited = false

ใช้ mock provider ที่มากับไลบรารี — รันได้ทันทีโดยไม่ต้องมี API key หรือเชื่อมต่ออินเทอร์เน็ต นี่คือ baseline แบบ pass-through ที่ยังไม่เปิด optimization ใดเลย ใช้เทียบผลก่อน/หลังเปิดแต่ละ stage
