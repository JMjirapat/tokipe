Go library · v1.0.0

tokipe

Cut the input-token cost of an LLM application without risking a single turn.

go get github.com/JMjirapat/tokipe

The problem

Every turn re-sends the whole conversation

An agent on turn 40 pays for turns 1–39 again. Retrieval pastes the same passage twice. A tool that was already called gets called again, and its output is billed again.

5005
billed input tokens, 12 turns, no optimization
195691
the same workload stretched to 100 turns

None of that is the model being expensive. It is the same bytes, paid for repeatedly.

What it is

An ordered pipeline that runs before the model call

request→ preprocess→ tool cache→ RAG→ dedupe→ compress→ history budget→ cache align→ routing→ send

A library, not a service. No global state, no daemon, no proxy in front of your traffic. You call kit.Run(ctx, req) and get a response.

The core module imports only the Go standard library. Enforced by CI on every push, not by convention.

Three rules

What you can rely on

1 · Everything is opt-in

Enable nothing and you get a pass-through. Add one stage at a time and measure each.

2 · Fail-open is absolute

No optimization may cost you a turn. Any stage that errors or panics is contained; the pipeline continues with the unoptimized request.

3 · Order is fixed

Stages run in a defined sequence, because cache alignment only works if it runs after everything that rewrites content.

Proof, not a promise

examples/observability -break breaks every dependency at once: 40/40 turns still succeed, 80 degradations logged.

Install

Core, plus only the backends you use

# the library — stdlib only, no transitive dependencies
go get github.com/JMjirapat/tokipe

# optional, each a separate module with its own deps
go get github.com/JMjirapat/tokipe/stores/pgvector   // retrieval
go get github.com/JMjirapat/tokipe/toolcache/redis   // shared tool cache
go get github.com/JMjirapat/tokipe/metrics/otel      // OpenTelemetry

Go 1.23+. Builds with CGO_ENABLED=0 on Linux, macOS and Windows.

Example · 60 seconds

The smallest thing that works

import (
    "github.com/JMjirapat/tokipe"
    "github.com/JMjirapat/tokipe/pipeline"
    "github.com/JMjirapat/tokipe/providers/mock"
)

kit := tokipe.New(mock.New("demo-model", "42"))

resp, err := kit.Run(ctx, &pipeline.Request{
    Query: "What is six times seven?",
})
content        = "42"
model          = demo-model
shortCircuited = false

The mock provider ships with the library, so this runs with no key and no network. Nothing is enabled yet — this is the pass-through baseline you measure everything else against.

Stage 1 · Preprocess

Answer it yourself; never call the model

Some questions you already know the answer to. A Rule catches those before anything else runs.

config.WithPreprocess(
    preprocess.RuleFunc{
        RuleName: "help",
        Match: func(r *pipeline.Request) bool {
            return r.Query == "/help"
        },
        Fn: func(r *pipeline.Request) (*pipeline.Response, error) {
            return &pipeline.Response{Content: menu}, nil
        },
    },
)
"ping"            → "pong"   shortCircuited=true
"explain quantum" → "…LLM…"  shortCircuited=false

The only stage that saves 100%. Everything else makes the request smaller. This one removes it. In the benchmark, 3 of 12 turns never reach the model.

Stage 1 · Preprocess

Two gates, on purpose

CanHandle — cheap and rough

Runs on every request. Keep it to a glance. The shipped JSON rule looks at one character:

switch p[0] {
case '{', '[', '"', 't', 'f', 'n', '-':
    return true
}

Handle — expensive and exact

Runs only for requests that passed the gate. Here it is a real parse:

json.Unmarshal([]byte(p), &out)

Returning nil means “I could not handle it after all” — the pipeline moves on to the next rule, or to the model. That escape hatch is why the first gate is allowed to be sloppy.

Be strict. A rule that claims a request it should not have answers the user wrong, with no model to catch it. When in doubt, return false — one model call is far cheaper than one wrong answer.

Stage 2 · Tool cache

Identical arguments run once

config.WithToolCache(
    toolcache.NewMemoryCache(),
    exec,               // your tool executor
    time.Minute,        // TTL
)

Swap NewMemoryCache() for the Redis module and the cache is shared across processes.

turn 1 — executor invocations so far: 1
turn 2 — executor invocations so far: 1
turn 3 — executor invocations so far: 1

Three turns, one execution. The saving is double: the tool does not run, and its output is not re-billed as input tokens.

Concurrent identical calls collapse into one execution (singleflight), so a burst does not become a stampede.

Stages 3–5 · Context

Retrieve, then stop paying for it twice

RAG

Embed the query, pull top-K evidence. This adds tokens — it earns its place by letting you send five relevant passages instead of a whole document.

Dedupe

Retrieval routinely returns the same passage twice under two URLs. The second copy tells the model nothing and costs full price.

Compress

Lossless-ish trimming, plus an AST-aware compressor for Go source that understands what is safe to drop.

History budget

Trims the middle of the conversation — never the static prefix, never the newest message.

Dedupe defaults to exact normalized matching. Near-duplicate merging is opt-in, because “allow” and “deny” can differ by one word in a long document.

Stage 6 · Cache alignment

Mark what never changes

Messages: []pipeline.Message{
    {Role: "system", Content: prompt, Static: true},
    {Role: "user",   Content: "first turn"},
    ...
}

config.WithCacheAlignment()
breakpoints placed = 1
  after message 0 — reason "static_prefix"

Providers cache the longest matching prefix of a request. tokipe places the breakpoints, but you have to say which content is stable.

A breakpoint may only sit after Static content. That is the entire rule — and the prefix must stay byte-identical. Change one space in the system prompt and every cached turn is a miss.

Verified against a live Messages-API endpoint: turn 1 writes the prefix to the cache, turn 2 reads it back.

Stage 7 · Routing

Send easy turns to the cheap model

config.WithRouter(router.NewHeuristicRouter(
    router.Tier{Client: cheap,  MaxComplexity: 0.35},
    router.Tier{Client: strong, MaxComplexity: 1.0},
))
2 chars      → cheap-model
5543 chars   → strong-model

Know the defaults before you tune

weights            length 0.5, code 0.3, chunks 0.2
length saturation  8000 chars

A 500-character snippet full of code fences scores about 0.33: the code axis maxes out but contributes at most 0.3, and length barely moves. Put a tier boundary at 0.35 and it quietly goes to the cheap model.

This deck's own example hit exactly that on the first try.

Your own

Implement one method. Add SendStream and streaming works too — an optional interface, not a breaking change.

client, _ := cli.New(cli.ClaudePreset(workdir))
kit := tokipe.New(client, config.WithCacheAlignment())
Streaming

Incremental output, same pipeline

for delta, err := range kit.RunStream(ctx, req) {
    if err != nil { break }
    fmt.Print(delta.Text)
    if delta.Usage != nil {
        // final delta carries the accounting
    }
}

Every optimization still applies — the request is prepared by the same code path as Run, deliberately shared so the two cannot drift.

A client that does not implement streaming still works; the pipeline falls back to a single response.

Observability

A pipeline that stopped optimizing should not be silent

degraded: stage=preprocess reason=rule_canhandle_panicked
degraded: stage=preprocess reason=rule_returned_nil
content        = "hello"
shortCircuited = true

Two broken rules, and the turn still succeeded — with a record of exactly what failed.

Fail-open without reporting is indistinguishable from working. Every degradation carries the stage, a reason, and the offending component's name.

  • Latency histograms per stage
  • Counters for short circuits, cache hits, routing decisions
  • OpenTelemetry adapter in a nested module

config.WithMetrics wires the pipeline's recorder. The router keeps its own — pass one to NewHeuristicRouterWith or its decisions stay invisible.

Putting it together

A realistic configuration

kit := tokipe.New(client,
    config.WithMetrics(rec),
    config.WithPreprocess(rules...),
    config.WithToolCache(cache, executor, time.Minute),
    config.WithRAG(embedder, store, 5),
    config.WithChunkDedupe(),
    config.WithDefaultCompression(),
    config.WithHistoryBudget(budget.DefaultPolicy(), counter),
    config.WithCacheAlignment(),
    config.WithRouter(router.NewHeuristicRouter(
        router.Tier{Client: cheap,  MaxComplexity: 0.35},
        router.Tier{Client: strong, MaxComplexity: 1.0},
    )),
)

Add one line at a time and measure. Every option is independent, and a stage that does not help your workload is a stage you should not be running.
