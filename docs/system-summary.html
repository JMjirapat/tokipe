High-level system summary · v1 core + Delivery 2

Spend model tokens where they matter.

agentkit is an ordered Go pipeline that removes avoidable LLM work, shapes context for reuse, and chooses the right model—without becoming another service to operate.

Core principle

Optimizations are optional and fail open. If an optimization breaks, the request should still reach a usable model path.

01 · Request lifecycle

One request, progressively less waste.

The caller supplies a request and a default model. Each enabled capability gets one deliberate opportunity to reduce work before the final provider call.

01 Preprocess Answer known deterministic cases; stop here.
02 Tool cache Reuse repeatable tool results; execute misses.
03 RAG Embed the query and retrieve top-K evidence.
04 Dedupe Drop exact normalized duplicate evidence.
05 Compress Shrink JSON, prose, or complete Go source safely.
06 History Fit messages and chunks to the turn budget.
07 Custom Run caller-specific request shaping.
08 Align Place stable content first and safe breakpoints.
09 Route Score the final prompt; select the cheapest fit.
10 Model send Call or stream from an API, CLI, or custom backend.
11 Response Return a response or incremental deltas.

02 · Capabilities

Composable levers, one stable integration.

Applications keep building the same `pipeline.Request`. Cost and latency policy lives in composable options, not scattered conditionals across business code.

∅

Avoid calls

Preprocess rules return deterministic answers in-process, without spending tokens or launching a CLI.

↻

Avoid repeated work

Tool caching hashes name and arguments, reuses safe results, and coalesces concurrent identical misses.

R

Retrieve selectively

RAG runs only when the request opts in, adding top-K evidence through small embedder and store interfaces.

=

Remove duplicate evidence

Exact normalized duplicates are dropped safely; lossy near-matching requires an explicit lower threshold.

≪

Shrink safely

Compression minifies JSON, normalizes prose, and can parse complete Go files with directive-aware safeguards.

▰

Reuse prefixes

Cache alignment separates invariant instructions from history and per-turn evidence.

⇄

Route by complexity

A deterministic score over length, code density, and chunks selects a model tier after shaping finishes.

⋯

Stream optionally

Providers may emit incremental deltas; ordinary clients and deterministic answers remain compatible as one-delta streams.

↧

Load on demand

Protected references keep large files out of prompts until the application explicitly resolves them.

⌁

Bound growing context

Per-turn budgets trim middle history and lower-ranked chunks while protecting static and newest content.

◎

Observe degradation

Counters, latency histograms, context gauges, and stable degradation reasons make fail-open behavior visible.

04 · Failure model

Optimizations fail open.

Optional infrastructure should not turn a viable model request into an outage. Built-in extension calls are guarded, while cancellation and the final model error remain visible.

Cache down? Treat as a miss.
RAG down? Continue without chunks.
Compression fails? Keep original text.
Router fails? Use the default model.
Metrics fail? Drop diagnostics only.
Model fails? Return the error.
05 · Ownership

Clear boundaries keep the core portable.

The root module remains standard-library-only. Infrastructure drivers and application-specific policy stay outside the core.

agentkit core

Owns ordering, request flow, safe defaults, and stable interfaces.

  • pipeline and config
  • preprocess, dedupe, and compression
  • history, cache alignment, and routing
  • streaming and metrics contracts

Adapters

Translate small interfaces into real infrastructure and model calls.

  • Anthropic and OpenAI-compatible APIs
  • Claude, Codex, OpenCode CLIs
  • pgvector and Redis nested modules
  • OpenTelemetry nested module

Your application

Owns product policy, authorization, quality, and irreversible actions.

  • tool execution and cache safety
  • embedding implementation
  • turn budgets and lazy-load tools
  • timeouts, retries, and rollout
